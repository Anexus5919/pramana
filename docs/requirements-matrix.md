# Requirements matrix

Each requirement from PS 26261 is mapped to what implements it, how to see it in the demo, and the test that checks it. Paths are relative to `backend/`.

| # | Requirement (PS 26261) | Implementation | Demo evidence | Test |
|---|---|---|---|---|
| 1 | Identify the application category and the applicable checklist | `rulesets/aicte-aph-2024-27.yaml` `checklists` (EOA, INCREASE_INTAKE, from Annexure 2.1 and Add. 2026-27 Cl. 2.6); `GET /api/applications/{id}` returns `document_checklist` | Institution portal checklist slots; A10 is evaluated under the intake-increase rules | `test_planted_conditions_match_ground_truth` |
| 2 | Retrieve relevant institutional records from authorized systems | `ReferenceRecord` (approval history, faculty registry, accreditation, TER ledger, deficiency register) in `pipeline/facts_builder.py` | A4: declared intake 120 vs record 60 (`XR-INTAKE-RECORD`) | e2e ground truth |
| 3 | Identify missing, incomplete, expired, inconsistent documents | Rules `APH-A21-*` (presence, conditional SSC), `APH-617I-FIRE-VALID`, `APH-617H-SSC-VALID`, `XD-*` cross-document rules | A2 missing SSC; A3 expired fire certificate | e2e ground truth |
| 4 | OCR, classification and data extraction | `pipeline/text.py` (pdfplumber words), `pipeline/ocr.py` (RapidOCR), `pipeline/extract.py` (keyword classification, anchored patterns with word boxes) | A2 audited accounts uploaded as a scan; every field highlights its source region | Evaluation: 299/299 fields |
| 5 | Structured validation report, rectification where permitted | Validation runs with checklist, findings, digests; `POST /rectification`, institution re-upload and resubmit; out-of-scope change detection | A3 rectification round resolves the expiry finding | `test_rectification_round_resolves_and_flags_out_of_scope_changes` |
| 6 | Detect alterations, duplication, metadata and identifier anomalies, irregular dates | `forensics/pdf_struct.py` (revision diff, overlay, white boxes, metadata dates); `consistency/cross.py` (identical files, shared certificate numbers, near-duplicate field values, photo reuse); `FX-FIELD-OVERWRITTEN` | A7 date overwritten after signing; A5 NOC number reused; A10 photo reused | `test_overwrite_in_incremental_update_is_localised`, e2e |
| 7 | Each flag identifies evidence and reason, as a preliminary indicator | Every finding carries `evidence` (page and bbox regions, records, comparisons), `message`, `limitation`, `evidence_class`; wording never says forged or fake | Finding panel with highlighted regions and caution notes | Manual review of UI |
| 8 | Verify with issuing authorities, digital signatures, QR codes, reference numbers | `verification/signature.py` (pyHanko, CCA India roots), `verification/signed_qr.py` (JWS EdDSA), `verification/issuer.py` (adapter interface, simulated registries) | Real e-Gazette PDF verified against CCA India 2022 (Verify a PDF); A5 QR names another college | `test_signature_states`, `test_signed_qr_detects_tampering`, `test_india_pki_roots_are_bundled` |
| 9 | Record source, timestamp and result; statuses verified, mismatch, expired, pending, source unavailable, manual review | `VerificationAttempt` rows; statuses in `verification/base.py` plus `not_checked` | A9: source unavailable and pending; manual confirmation by the verification cell | e2e ground truth (status codes) |
| 10 | Route to manual confirmation when automated verification is unavailable or inconclusive | `POST /api/verifications/{id}/manual`; dashboard alerts for unavailable and pending sources | Verifier records a manual confirmation on A9 | API smoke test |
| 11 | Configurable checklists derived from the handbook | YAML ruleset: effective dates, citations with verbatim quotes, applicability conditions, `requires_docs`, norms tables | Rules page shows clause, page and quote for each rule | `test_rule_outcomes`, `test_rule_not_effective_before_its_start_date` |
| 12 | Infrastructure evidence: photos, floor plans, certificates; flag cases for more evidence or inspection | `forensics/image.py` (EXIF capture time, geotag distance, editing software), photo reuse via perceptual hash, OC area vs declared area, satellite-map distance | A10 photo geotag far from campus; A4 area beyond the OC; "Escalate for inspection" action | e2e ground truth |
| 13 | Dashboard: status, deficiencies, verification results, unresolved items, cases needing intervention | `GET /api/dashboard`, React dashboard and application workspace | Review queue, alerts panel | API smoke test |
| 14 | Automated alerts | Dashboard alerts for high-severity findings, unavailable sources and pending verification | Alerts panel | API smoke test |
| 15 | Audit trail of rules, records, source responses, alerts, actions | Hash-chained `AuditEvent` with Ed25519 checkpoints; runs pin ruleset hash, input digest, report digest | Audit tab: verify chain; replay a run | `test_audit_chain_detects_tampering`, `test_replay_reproduces_the_report` |
| 16 | Role-based access, secure handling, confidentiality | Server-side sessions, CSRF header, roles, object-level checks (404 across institutions), Fernet encryption at rest, upload validation | Institution login sees only its own application and deficiencies | `test_institutions_cannot_see_each_other`, `test_csrf_and_reasons_are_enforced`, `test_upload_validation`, `test_active_content_is_reported` |
| 17 | Human review before any adverse action | Review actions need reasons for accept, dismiss and escalate; no endpoint approves or rejects an institution | Finding review panel | `test_csrf_and_reasons_are_enforced` |
| 18 | Demonstrate with synthetic data; measure accuracy, verification and processing time | `scripts/make_fixtures.py`, `scripts/seed.py`, `scripts/evaluate.py` | `docs/evaluation-results.md` | `scripts/evaluate.py` |
